# Работа с учебником JKids

Репозиторий: `Dagar165/jkids-guides`. Главная: `https://dagar165.github.io/jkids-guides/`.
GitHub Pages публикует ветку `main`, папку `/ (root)`. Материалы публичны: без паролей, ключей, личных данных интервьюируемых и внутренних документов, которые пользователь не поручал публиковать.

## Добавить методичку

1. Прочитай этот файл, `README.md`, `METHOD.md` и текущий `catalog.json`. Уточни slug только если есть неоднозначность; обычно выбери короткий английский slug по теме.
2. Создай `guides/<slug>/index.html` и `guides/<slug>/guide.json`. Скопируй структуру метаданных из `templates/guide.json`; замени все значения, включая дату добавления. У всех материалов один вид — методичка. В `outcomes` запиши 1–5 конкретных действий, которые тренируются; тип источника не создаёт категорию на главной.
3. Методичку составляй по предоставленной расшифровке. Не сокращай содержательные объяснения и примеры ради дизайна. Понятно отделяй факты и случаи из лекции от редакторских пояснений, применения к JKids и гипотез. Если источник недоступен, скажи об этом и не достраивай содержание.
4. Построй обучение по `METHOD.md`: действие и смысл, база, полный материал источника, решение с рассуждением, самостоятельная задача с объяснением ответа, перенос и критерии. Для бланков обязателен заполненный образец со смыслом полей. Не создавать раскрывашки с повтором первого предложения; не объявлять навык освоенным после чтения.
5. Обеспечь читабельность на телефоне, поиск и навигацию внутри длинной методички. Добавь обычную ссылку `<a href="../../">Все методички</a>`. Не загружай другие методички, внешние шрифты или библиотеки. Ссылки на темы должны открываться напрямую. Локальные черновики ответов не выдавай за отправленные команде. Весь каталог не встраивай внутрь каждой лекции.
6. Запусти `python3 scripts/build_catalog.py`, затем `python3 scripts/build_catalog.py --check`. Скрипт собирает карточки из отдельных `guide.json`. `catalog.json` — автоматически полученное оглавление; вручную его не редактируй.
7. Проверь открытие карточки, возврат в каталог, поиск и сохранность исходного содержания. Опубликуй готовые файлы вместе в `main`, чтобы папка и карточка появились одним изменением. До изменения структуры сохрани снимок содержания; после сверь блоки, таблицы, формы и оговорки с ним. Проверяй не только наличие заданий, но и их выполнимость на данных раздела и полезность объяснения ответа. Проверь GitHub Actions `pages build and deployment`, затем фактическое открытие опубликованного сайта.
8. В ответе дай постоянную главную ссылку и кратко скажи, что добавлено. Доступность без VPN в России утверждай только после проверки из России или сообщения пользователя.

## Обновить материал

Изменяй только `guides/<slug>/` нужной методички. Если меняются название/описание/действия/теги, обнови её `guide.json` и пересобери каталог. Не переписывай чужие методички или оболочку без причины. Сохраняй slug: уже отправленные ссылки должны продолжать работать.

## Работа через GitHub-подключение

Перед записью прочитай текущую ветку и затрагиваемые файлы. Для замены используй актуальный blob SHA. Предпочитай один Git tree/commit с родителем из текущего `main` и обновление ref без `force`. Если ветка изменилась, перечитай её и перенеси свои изменения, сохранив новые материалы.
Если нет локального checkout, собери изменённые файлы локально и проверь их. Для пересборки каталога понадобятся все `guide.json`, но полные тексты остальных методичек читать и загружать не нужно: неизменённые страницы можно сохранить их текущими blob SHA. Проверку существующих страниц используй из уже проверенного дерева; не выдумывай её выполнение локально.

## Производительность

Главная загружает только HTML/CSS/JS оболочки и маленький `catalog.json`. Методичка загружается при переходе в свою папку. Не создавай общий файл со всеми текстами, скрытые iframe или предварительную загрузку всех лекций. Изображения оптимизируй и включай `loading="lazy"` для контента ниже первого экрана. Следи за ростом размера каталога и оболочки; тяжелый материал должен влиять только на собственную страницу.

GitHub хранит код и опубликованный учебник. Исходные расшифровки и рабочие решения А:Старт/JKids сохраняют свои канонические места на Google Диске; сайт не превращай во второй архив внутренних решений.
